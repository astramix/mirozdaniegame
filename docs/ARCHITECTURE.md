# Архитектура «Мироздания»

Цель архитектуры: десятки тысяч сущностей, глубокая логика и красивое отображение, при этом всё проверяемо тестами в облаке без экрана.

## Структура репозитория

```
mirozdanie/
├── RULES.md                  правила проекта
├── NOTES.md                  журнал решений и источников
├── Mirozdanie.sln
├── src/
│   ├── Mirozdanie.Core/        вся симуляция, чистый C#, без Godot
│   ├── Mirozdanie.Core.Tests/  xUnit: правила, детерминизм, научные проверки
│   ├── Mirozdanie.Bench/       BenchmarkDotNet: бюджеты производительности
│   └── Mirozdanie.Cli/         прогон миров без отрисовки, PNG-карты, отчёты
├── game/                     Godot-проект (C#), ссылается на Core
│   ├── scenes/  scripts/  shaders/  theme/  locale/
├── docs/
│   ├── PLAN.md  ARCHITECTURE.md
│   ├── design/               дизайн-документ на каждую подсистему
│   ├── screenshots/
│   └── diversity-report.md
└── .github/workflows/        CI и сборки релизов
```

Правило зависимостей: `game` → `Core`. Никогда наоборот. Core не знает, как его рисуют.

## Ядро симуляции

### Данные, а не объекты

Тысячи сущностей нельзя хранить как тысячи объектов с виртуальными методами. Core устроен data-oriented:

- Сущности одного типа лежат в пулах со структурой массивов (struct of arrays): `float[] X, Y, Energy`, `int[] SpeciesId` и т.д. Идентификатор сущности — индекс плюс поколение (чтобы ссылка на умершую особь не указывала на новую).
- Системы — это функции, которые проходят по массивам: `Metabolism.Tick(world)`, `Movement.Tick(world)`, `Belief.Tick(world)`. Порядок систем задан явно в одном месте.
- Никаких аллокаций в горячем цикле: пулы, `Span<T>`, заранее выделенные буферы.
- Поиск соседей через пространственную хеш-сетку, а не перебор всех со всеми.

### Уровни детализации

| Уровень | Сущность | Типичное количество |
|---|---|---|
| Клетка мира | климат, ресурсы, популяции видов | 512×256 = 131 072 |
| Особь | отдельное существо с геномом | до 20 000+ |
| Группа | племя, народ, культура | сотни |
| Полития | государство | десятки |
| Персонаж | лидер, пророк, учёный | сотни |

Правила перехода описаны в дизайн-документах: особи в плотной популяции «сворачиваются» в популяцию клетки, разумные стаи становятся группами, группы объединяются в политии. Обратно — при зуме: жители города генерируются из статистики группы детерминированно (сид = сид мира + id группы + номер жителя).

### Время

- Фиксированный шаг тика. Длительность тика в игровом времени зависит от эпохи.
- Разные системы могут работать с разной частотой: движение — каждый тик, климат — раз в сезон, политика — раз в год.

### Детерминизм

- Свой RNG (xoshiro256** или PCG), отдельный поток на каждую подсистему, чтобы изменение одной системы не сдвигало случайности в других.
- Порядок обхода всегда стабильный, никаких словарей с непредсказуемым порядком в логике.
- Многопоточность только там, где результат не зависит от порядка (например, расчёт климата по независимым клеткам).
- Сохранение: периодический полный снимок + журнал вмешательств Создателя после него.

### События и Хроника

- Все значимые изменения пишутся в журнал событий: тип, время, участники, место, значимость.
- Системы подписываются на события (вера реагирует на чудеса, политика — на голод).
- Хроника, лента событий и толкования культур строятся из этого журнала.

## Связь с Godot

- Симуляция работает в отдельном потоке. После каждого тика она публикует неизменяемый снимок для отрисовки (двойная буферизация). Godot читает только снимок, команды игрока передаёт через очередь.
- Интерфейс никогда не лезет во внутренние массивы Core напрямую.

## Отрисовка тысяч сущностей

- Карта делится на чанки (например 64×64 клетки). Каждый чанк — текстура, которую Core-данные заполняют напрямую; перерисовываются только изменившиеся чанки.
- Существа, отряды, корабли рисуются через `MultiMeshInstance2D` — один вызов отрисовки на тысячи спрайтов.
- Процедурные спрайты (существа, здания, портреты, иконки) генерируются при запуске или при появлении вида/культуры и складываются в атлас текстур.
- Вода, облака, день и ночь, сезоны, туман неизвестного — шейдеры.
- При отдалении особи заменяются плотностью популяций, при приближении — отдельными спрайтами.

## Интерфейс

- Godot Control-узлы и одна тема (Theme resource) с перекрашиванием под палитру культуры.
- Все строки — через CSV-переводы Godot.
- Окна, радиальное меню, диалоги — отдельные сцены, получают данные только из снимка.

## Бюджеты производительности

Проверяются бенчмарками в CI. Значения стартовые; если раннер CI заметно медленнее, сессия фиксирует коэффициент в NOTES.md.

| Операция | Бюджет |
|---|---|
| Тик с 20 000 особей | ≤ 8 мс |
| Тик поздней эпохи (сотни групп, десятки политий) | ≤ 8 мс |
| Генерация мира 512×256 | ≤ 3 с |
| Прогон 1000 лет без отрисовки (CLI) | ≤ 60 с |
| Публикация снимка для отрисовки | ≤ 1 мс |

## Зависимости

Минимум. Разрешены: xUnit, BenchmarkDotNet, при необходимости библиотека сериализации для сохранений. Любая новая зависимость записывается в NOTES.md с причиной.
