# Правила проекта «Мироздание»

Читай этот файл в начале каждой сессии. Затем `docs/PLAN.md` (что строим), `docs/ARCHITECTURE.md` (как устроено) и `NOTES.md` (где остановились).

## Проект

Процедурный симулятор Создателя: от первичной жизни до цивилизации Кардашёва I. Godot 4 + C#. Симуляция в `src/Mirozdanie.Core` без зависимостей от Godot; `game/` только отображает.

## Команды

```
dotnet build Mirozdanie.sln
dotnet test src/Mirozdanie.Core.Tests
dotnet run -c Release --project src/Mirozdanie.Bench -- --filter '*'
dotnet run -c Release --project src/Mirozdanie.Cli -- run --seed 42 --years 1000 --out out/
```

Godot (без экрана): `godot --headless --path game --quit-after 300` как дымовой тест. Если Godot или .NET SDK не установлены в облачной машине, поставь их в начале сессии и запиши способ в NOTES.md (раздел «Окружение»), чтобы следующая сессия сделала это быстрее.

## Порядок работы над подсистемой

1. **Дизайн.** Напиши `docs/design/<подсистема>.md`: переменные, формулы, научная основа с источниками, связи с другими системами (какие события слушает и порождает), настраиваемые параметры, как это проявится в игре, как проверить тестом. Остановись и попроси одобрения автора.
2. **Реализация** только по одобренному дизайну. Если по ходу понадобилось отступить — обнови дизайн-документ и объясни почему.
3. **Тесты и бенчмарки** вместе с кодом, не после.
4. **Итог этапа:** все тесты зелёные, бенчмарки в бюджете, NOTES.md обновлён, коммит, PR с описанием, короткий отчёт автору: что работает, что нет, что стоит посмотреть глазами.

## Неприкосновенные правила

- Детерминизм: только RNG проекта, стабильный порядок обхода, никаких `DateTime.Now`, `Random` или `HashSet`-порядка в логике.
- Никаких аллокаций в горячих циклах симуляции.
- Core никогда не ссылается на Godot.
- Ничего не прописывать «вручную» там, где план требует процедурной генерации: религии, языки, имена, экономики, архитектура выводятся из состояния мира.
- Никаких внешних ассетов, копий чужой графики, реальных религий, народов и языков.
- Не удалять и не ослаблять тест, чтобы он прошёл. Если тест неверен — объясни в PR.
- Маленькие осмысленные коммиты. Одна ветка на этап: `stage/e2-life` и т.п.

## Стиль кода

- C# с включёнными nullable и предупреждениями как ошибками в Core.
- Имена в коде по-английски, комментарии и документы можно по-русски.
- У каждой формулы комментарий со ссылкой на источник или на дизайн-документ.

## Когда не уверен

Не угадывай молча. Запиши вопрос в отчёт и в NOTES.md, выбери самый простой обратимый вариант и продолжай.
